# Nâng cấp Agent Fleet 1.1.0

Ngày: 03/11/2026.

## Vấn đề được xác nhận

Bài thử thật giao cùng nhiệm vụ tạo `hello.txt` và chạy `node check.cjs` cho
Qoder, AGY, Codex và OpenCode. Các agent đều tạo file đúng. Riêng AGY bị từ chối
quyền chạy lệnh ở chế độ headless nhưng vẫn thoát với mã 0; fleet 1.0.0 ghi
`done`, `checkPassed: true`, `finalMessage: null` do check độc lập của fleet đạt.
Vì vậy trạng thái cũ che mất việc agent chưa hoàn thành brief.

## Thay đổi trong bản này

- Nhận diện lỗi quyền từ sự kiện tool của AGY và thông báo stderr headless.
  Giữ nguyên log gốc, đồng thời phát sự kiện lỗi `permission` dễ thấy.
- Nhận diện kết quả AGY có trạng thái lỗi, kể cả tiến trình thoát với mã 0.
- Run có sự kiện lỗi không còn được đánh dấu `done` chỉ vì exit code bằng 0.
- Check độc lập vẫn chạy sau lỗi quyền nếu agent thoát 0; check PASS không xoá
  lỗi agent. Check FAIL chuyển run sang `failed`, nhóm lỗi `check`.
- `fleet wait` trả mã 1 khi có lỗi hoặc check FAIL, kể cả dữ liệu `done` từ bản cũ.
- Merge bị chặn trước khi commit nếu run có check FAIL hoặc lỗi agent.
- CLI in hướng dẫn xử lý và lệnh xem log; UI hiển thị PASS/FAIL và lỗi quyền.
  Chỉ task `done` mới có nút Merge; dữ liệu cũ có lỗi không thể bấm Merge.
- Bổ sung kiểm thử parser, runner, lifecycle, CLI, UI và E2E cho các lỗi này.

## Quyền chạy lệnh của AGY

Mặc định giữ `--mode accept-edits`. Không tự mở rộng quyền hoặc thêm
`--dangerously-skip-permissions`.

Có hai cách xử lý khi task cần lệnh chưa được cho phép:

1. Mở `fleet ui`, chọn task, bấm **Mở terminal** để tiếp tục phiên AGY và duyệt
   quyền tương tác. Không mở terminal thứ hai để sửa cùng worktree khi agent
   headless vẫn chạy.
2. Cấp trước đúng lệnh qua `permissions.allow` trong AGY. Có thể truyền
   `--settings` qua `agents.agy.extraArgs` của fleet để áp dụng cấu hình phiên.
   Xem ví dụ trong [hướng dẫn leader](../leader-guide.md). Chỉ người vận hành chọn lệnh được cấp.

Sau khi xử lý quyền, dùng `fleet retry <task-id> --note "Đã xử lý quyền; hoàn tất
brief và chạy lại kiểm tra"` để fleet ghi nhận kết quả và check của lần chạy mới.

## Tương thích và áp dụng

- Không đổi schema SQLite; lịch sử và worktree hiện có được giữ nguyên.
- Thêm giá trị `permission` và `check` cho `errorCategory`.
- Thay đổi có chủ ý: check FAIL nay là task `failed`, không còn là `done`.
- Các task lịch sử không bị sửa hồi tố. CLI và merge kiểm tra cả dữ liệu cũ.
- Cần build lại web và khởi động lại server để áp dụng đầy đủ.

## Hướng tiếp theo

- Quyền theo task trong CLI/UI, có danh sách lệnh cụ thể và được lưu theo lần chạy.
- Phát hiện trạng thái sẵn sàng về đăng nhập/quyền; `doctor` hiện mới kiểm tra CLI.
- Luồng hoàn tất và chạy lại check sau tiếp quản terminal ngay trên UI.
- Bài smoke test nhiều agent thành lệnh riêng, xuất báo cáo tổng hợp.
